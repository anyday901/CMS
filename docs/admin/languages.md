# Languages

The client portal, the store, the public support pages and client emails can be shown in more than one language. CMS ships English, German, French and Spanish.

## Offering languages

Under **Settings**, in the **Languages** section, pick the **main language** and list the **other languages** to offer, such as `de, fr`. Then:

- visitors get the language their browser asks for, if it's offered, and can pick another with the picker at the bottom of portal pages;
- signed-in clients keep the language they pick on their account, and staff can set it on the client's page (**Language**);
- a client's emails are sent in their language, with dates written in it too;
- knowledge base articles and announcements can be translated into each language, as before.

## Portal text

**Settings > Portal text and translations** lists every language with how much of the portal text it has. Open one to search the strings, see only the missing or changed ones, and type your own wording. Your wording wins over the shipped translation and survives updates; clear a field to go back to the shipped text.

This also works for a language CMS doesn't ship: offer it, then translate the strings here. Anything not translated shows in English.

## Emails

**Email templates** has a tab for each language offered. A template in another language starts from the translation CMS ships, if there is one; save it to make it yours. Clients whose language has no translation get the main language's version. Turning an email off is done on the main language's tab and applies to all languages.

## Contributing a translation

To add a language to CMS itself for everyone, see [Translations](../developers/translations.md).
